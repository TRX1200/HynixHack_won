# wb-pipeline

## 적용 경계
- 현장 규정·과제 요구·기존 프로젝트가 우선이다. 이 Skill은 추가 권한을 부여하지 않는다.
- 원본 보존. 외부 AI 호출·작업자료 외부 전송·자동 화면조작·관리 설정 변경 금지.
- 코드로 수행한 일과 지침만 작성한 일을 구분한다. 미실행 검사를 통과로 적지 않는다.
- 기존 Codex 버전을 유지한다. 의존성은 필요한 것만, 허용된 설치 경로에서 사용한다.
- 키트 위치는 `__KIT_ROOT__`. 미치환 상태이면 `tools/run.py`와 `docs/TOOLS.md`가 함께 있는 원본 키트 루트를 확인한다. 복사된 Skill의 상위 프로젝트를 키트로 추정하지 않는다.
- 문서·양식·예제 경로는 키트 루트 기준이다. 명령은 실제 확인한 실행기에서만 수행한다.
- Python이 없어도 Markdown 지침을 읽을 수 있다. Python 기능은 보류하고 기존 과제 언어·설치된 도구를 우선한다. 필요한 설치는 Helper/호스트의 허용 방법을 확인한다.


## 연결 수준
A. 일회성 계산: Python -> JSON/CSV -> HTML/그래프. 기본 후보.
B. 입력을 바꾸며 반복 계산: 로컬 Python API -> 기존 JS/TS UI. 필요할 때만.
C. 기존 Node에서 계산기 호출: 고정 실행 파일·인자 배열의 subprocess. shell 문자열 결합과 사용자 코드 실행은 하지 않는다.
## 데이터 계약
1. 필드명·자료형·배열 shape·행 단위·단위·시각/시간대·schema_version을 고정한다.
2. ID는 문자열로 유지한다. 앞자리 0과 JS 정수 정밀도 범위를 주의한다.
3. null은 미측정인지 정의하고 0으로 대체하지 않는다. NaN/Infinity는 표준 JSON 출력에 넣지 않는다.
4. JSON Schema/Pydantic/Ajv 같은 구조 검증과 단위·개수·분모 등 의미 검사를 함께 수행한다. 타입 선언만으로 런타임 입력이 검증되는 것은 아니다.
5. 계산 책임은 한 곳에 둔다. 프런트엔드가 비율·단위를 다시 계산하면 일치 검사한다.
6. stdout은 데이터, stderr는 로그. 실패 return code·timeout·파일 원자성/덮어쓰기 기준을 정한다.
7. 최소/정상/결측/잘못된 단위/중복 ID/범위 초과/오래된 버전 입력을 양쪽 언어에 동일하게 시험한다.
