# wb-stats

## 적용 경계
- 현장 규정·과제 요구·기존 프로젝트가 우선이다. 이 Skill은 추가 권한을 부여하지 않는다.
- 원본 보존. 외부 AI 호출·작업자료 외부 전송·자동 화면조작·관리 설정 변경 금지.
- 코드로 수행한 일과 지침만 작성한 일을 구분한다. 미실행 검사를 통과로 적지 않는다.
- 기존 Codex 버전을 유지한다. 의존성은 필요한 것만, 허용된 설치 경로에서 사용한다.
- 키트 위치는 `__KIT_ROOT__`. 미치환 상태이면 `tools/run.py`와 `docs/TOOLS.md`가 함께 있는 원본 키트 루트를 확인한다. 복사된 Skill의 상위 프로젝트를 키트로 추정하지 않는다.
- 문서·양식·예제 경로는 키트 루트 기준이다. 명령은 실제 확인한 실행기에서만 수행한다.
- Python이 없어도 Markdown 지침을 읽을 수 있다. Python 기능은 보류하고 기존 과제 언어·설치된 도구를 우선한다. 필요한 설치는 Helper/호스트의 허용 방법을 확인한다.


## 먼저 구분
기술통계(무슨 일이 있었나), 추론(모집단 차이/관계), 예측(새 입력), 인과(개입 효과)는 다른 질문이다.
## 절차
1. 분석 단위와 독립 표본을 정한다. 반복 측정/로트/환자/설비/시간 의존성이 있으면 행 수를 독립 n으로 취급하지 않는다.
2. 분모·단위·결측·제외 기준을 정하고 분포와 표본 수를 먼저 확인한다.
3. 동일 대상 전후면 paired 후보, 별개 독립 집단이면 independent 후보다. 정규성·분산·표본설계·검정 방향을 확인한다. Welch도 독립성 문제는 해결하지 않는다.
4. 효과 크기와 불확실성 구간을 우선 기록하고 p값만으로 의미/인과/안전성을 주장하지 않는다. 다중 비교/반복 탐색을 기록한다.
5. 회귀는 잔차/이상치/공선성/오차 구조를 본다. 관측 상관을 원인으로 단정하지 않는다.
6. 예측이면 시간·그룹 경계를 고려해 split하고, 전처리·특징 선택·모델 선택을 train/validation 내부에서 수행한다. test 반복 튜닝 금지.
7. bootstrap/permutation은 표본 교환가능성·의존성에 맞는 단위로 사용한다. iid bootstrap을 시간 의존 데이터에 자동 적용하지 않는다.
8. 같은 결과를 다른 계산 또는 합성 정답으로 확인한다. 가정이 불명확하면 기술통계와 한계를 먼저 제시한다.
## 후보
SciPy stats: 검정/분포/재표집. statsmodels: 회귀/진단. scikit-learn: 예측/검증 Pipeline.
통계 함수는 연구 설계를 대신 정하지 않는다. 추가 모델/가중치의 사용 허용 여부는 별도로 확인한다.
