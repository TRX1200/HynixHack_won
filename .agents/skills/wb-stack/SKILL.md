# wb-stack

## 적용 경계
- 현장 규정·과제 요구·기존 프로젝트가 우선이다. 이 Skill은 추가 권한을 부여하지 않는다.
- 원본 보존. 외부 AI 호출·작업자료 외부 전송·자동 화면조작·관리 설정 변경 금지.
- 코드로 수행한 일과 지침만 작성한 일을 구분한다. 미실행 검사를 통과로 적지 않는다.
- 기존 Codex 버전을 유지한다. 의존성은 필요한 것만, 허용된 설치 경로에서 사용한다.
- 키트 위치는 `__KIT_ROOT__`. 미치환 상태이면 `tools/run.py`와 `docs/TOOLS.md`가 함께 있는 원본 키트 루트를 확인한다. 복사된 Skill의 상위 프로젝트를 키트로 추정하지 않는다.
- 문서·양식·예제 경로는 키트 루트 기준이다. 명령은 실제 확인한 실행기에서만 수행한다.
- Python이 없어도 Markdown 지침을 읽을 수 있다. Python 기능은 보류하고 기존 과제 언어·설치된 도구를 우선한다. 필요한 설치는 Helper/호스트의 허용 방법을 확인한다.


## 선택 순서
1. README·기존 코드·lockfile·실행기·실제 설치 버전을 먼저 확인한다. 기존 스택을 취향으로 재작성하지 않는다.
2. 문제의 계산과 표시 요구를 나눈다. 정적 보고서면 서버·프런트엔드를 추가하지 않는다.
3. 과학/통계/영상 계산은 Python을 기본 후보, 브라우저 동작은 기존 JS/TS를 기본 후보로 둔다. SQL은 언어 대체가 아니라 표 조회 계층이다.
4. 작은 웹 도구는 기존 JS/TS 하나로 끝낼 수 있으면 Python 서버를 추가하지 않는다.
5. C++/Rust 등은 기존 프로젝트가 요구하거나 실제 측정한 병목이 있을 때만 고려한다. 컴파일·FFI·배포·검사 비용을 같이 본다.
6. MATLAB은 실행환경/라이선스를 가정하지 않는다. 필요한 식과 알고리즘의 이식 가능성을 따진다.
7. 설치 실패 시 표준 라이브러리·이미 설치된 도구·정적 결과로 기능을 축소한다. 관리 설정 변경으로 해결하지 않는다.
## 기록
대안 2개, 채택 이유, 제외 이유, 필요한 실행기·의존성, 테스트 결과, fallback을 짧게 기록한다.
