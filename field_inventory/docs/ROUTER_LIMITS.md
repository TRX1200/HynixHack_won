# 라우터의 한계

`inventory.py`는 로컬 어휘·별칭·규칙과 작업 유형을 이용하는 **결정적 휴리스틱 검색기**다.
의미를 이해하는 모델·실행 솔버·독립 검증기가 아니다. 숫자 점수는 상대적 추천 순위이지
정답 확률·성능·정확도·최적성 보증이 아니다.

- 기본 추천은 최대 6개다. 먼저 필요한 2개만 `show`로 읽고, 여러 분야라도 처음에 6개를 넘겨 상세 로딩하지 않는다.
- 프로필에는 원문으로 확인한 사실만 적는다. 미확정 조건은 따로 남기고 값·상한·목표를 만들어 넣지 않는다.
- 표면적 단어가 같아도 실제 입력·목적·제약이 다르면 다른 알고리즘이 필요하다.
- `REVIEW_REQUIRED`·경고·제외 조건이 있으면 자동 채택을 보류한다. 모호한 추천은 원문과 대조한다.
- 라이브러리 이름이 나와도 설치·실행 권한·실제 import 성공은 별도 확인 대상이다.
- `RECIPE_ONLY` 카드와 `implemented: false` 코드 패턴은 아직 구현되지 않은 참고 설명이다.
- 한 작업 유형의 추천만으로 전체 프로젝트 구조를 확정하지 않는다. 기존 코드와 실제 인터페이스를 우선한다.
- 라우터의 합성 테스트는 해당 추천 규칙만 검사한다. 선택된 알고리즘의 정답·시간·품질을 검증하지 않는다.

추천 이후에는 선택한 카드와 대안 한 가지의 적용·제외 조건을 확인하고 최소 구현 한 건을 실제 실행한다.
독립 검증·실패 사례·실제 출력이 없으면 성공이나 전역 최적성을 주장하지 않는다.
