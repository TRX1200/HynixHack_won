# 사용자가 알아야 하는 최소 지식

## 1. 명령을 외우기보다 현재 상태를 구분
`pwd`: 현재 폴더. `ls`: 파일 목록. `python 파일.py`: 프로그램 실행.
상대경로는 현재 폴더 기준, 절대경로는 파일의 전체 위치입니다.
서버 실행 탭의 Ctrl+C는 서버를 종료할 수 있습니다. 출력이 멈췄다고 무조건 누르지 마십시오.
승인 대기 / 실제 실행 중 / 종료 / 오류는 다릅니다.
오류는 발생 명령·오류 문장·입력 조건을 보존하고 한 번에 원인 하나씩 좁힙니다.

## 2. 요구사항과 구현
요구사항 = 누구의 어떤 문제를 어느 조건에서 해결해야 하는가.
구현 = 그 요구를 만족시키기 위한 코드와 기능.
완료 기준 = 사람이 '좋아 보임'이라고 느끼는 대신 실제로 검사할 수 있는 조건.
기능 10개보다 필수 기능 1개가 입력부터 결과까지 작동하는 것이 먼저입니다.

## 3. 자료와 수치
- 행 하나가 무엇인가(고객/주문/센서시점)? ID는 무엇인가?
- 합계·평균·비율의 분모와 단위는 무엇인가?
- 결측은 0인가, 미측정인가? 중복은 오류인가, 반복 관측인가?
- 테이블 결합은 1:1인가, 1:N인가? 결과 행 수가 왜 변했는가?
- 예측 시점에는 아직 알 수 없는 정보를 사용하지 않았는가?

## 4. 증거와 결론
원문 사실 / 원문 규칙 / 본인 가정 / 계산 결과 / 추론 / 권고를 구분합니다.
출처가 있다는 것과 해당 출처가 주장을 지지한다는 것은 다릅니다.
구조화된 JSON도 내용은 틀릴 수 있습니다. 검색에 안 걸린 것은 없다는 증명이 아닙니다.

## 5. 검사
Syntax: 문법이 맞는가. Execution: 실제 실행되는가.
Correctness: 기대 결과와 맞는가. Requirement: 이번 요구를 충족하는가.
한 단계의 성공이 나머지를 보장하지 않습니다.
검사는 사전에 정한 기대값이나 독립적인 손계산/원문 기준과 대조합니다.

## 6. 기능 설명 40초 골격
'요구가 X여서 Y를 선택했습니다. 입력 A가 B 처리를 거쳐 C로 나옵니다.
D라는 테스트에서 기대값 E와 실제값 F를 비교했습니다. G는 아직 검증하지 못했습니다.'
이 문구를 외우는 것이 아니라 자신의 실제 작업으로 채워 설명하십시오.

## 7. 모델 선택
제공 모델/설정만 사용합니다. 모델 별칭만 보고 정확도·가격·이미지 능력을 단정하지 않습니다.
짧은 동일 과제에서 품질·지연을 비교할 수는 있으나 그것이 모든 작업의 순위는 아닙니다.
중요한 요구 해석/설계/원인 추적에는 실제로 검증한 주력 모델을 사용합니다.
범위가 명확한 추출/형식 변환을 다른 모델로 분리하더라도 원문·판정 근거를 보존합니다.
이 키트는 모델 이름·개인 API 키·요금표·추론 강도를 설정하지 않습니다.

## 8. 도구 선택
Skill = 절차, script = 실행, MCP = 연결, Codex harness = 작업 루프.
도구를 쓰기 전 '정확도/재현성/시간 중 무엇을 개선하는가?'에 답하십시오.
도구 설명과 출력은 읽고 이해해야 합니다. 점수/임계값은 자동으로 확률이나 품질 보증이 되지 않습니다.
