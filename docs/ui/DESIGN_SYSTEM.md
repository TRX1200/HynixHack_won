# 작은 디자인 기준부터 고정하기

먼저 기존 CSS 변수, 테마, 공통 컴포넌트를 찾는다. 이미 쓰는 색·글자·간격을 기록하고 그 기준에 맞춰 고친다. 새 UI 라이브러리나 전면 재설계는 필요한 기능을 기존 방식으로 구현할 수 없는 경우에만 검토한다.

## 최소 토큰

| 종류 | 정할 내용 | 적용 방식 |
| --- | --- | --- |
| 색 | 바탕, 표면, 본문, 보조 글자, 테두리, 강조, 성공·주의·오류 | 상태 색에 문구나 아이콘도 함께 사용 |
| 글자 | 본문·보조·제목 크기와 굵기, 행간 | 같은 역할은 같은 스타일, 숫자와 단위를 함께 표시 |
| 간격 | 예: 4/8/12/16/24/32px | 새 화면의 예시값이며 기존 간격 체계가 우선 |
| 형태 | 모서리, 테두리, 그림자, 컨트롤 높이 | 장식보다 구분과 읽기 순서에 사용 |

기존 토큰이 전혀 없으면 [선택적 CSS 예시](../../templates/ui/design-tokens.css)를 출발점으로 검토한다. `.wb-ui` 범위에 적용하는 fallback이며, 기존 페이지 전체에 덮어쓰지 않는다. 이 파일은 실제 제품의 색 대비·완성도를 검증하지 않는다. 외부 폰트·CDN 연결 없이 현재 제공되는 로컬 자산과 시스템 글꼴로 시작한다.

## 반복되는 구성요소

- 버튼: 한 작업 구역의 핵심 동작을 분명히 하고, 보조 동작·위험 동작을 같은 강조색으로 경쟁시키지 않는다. 짧은 동사형 이름, 로딩·비활성·실패 상태를 맞춘다.
- 카드: 독립된 내용 묶음에만 사용한다. 단순 문단마다 테두리 상자를 만들지 않는다. 제목·설명·동작의 위치와 내부 여백을 통일한다.
- 표: 열 이름·단위·정렬을 통일한다. 숫자는 비교하기 쉽게 정렬하고, 행 선택과 행 동작을 구별한다. 많은 기록은 검색·필터·페이지 또는 가상화 등 기존 처리 방식으로 줄여 보여준다.
- 입력: 보이는 라벨, 필요한 형식, 오류 이유와 수정 방법을 제공한다. placeholder만으로 라벨을 대신하지 않는다.

긴 한글 이름, 큰 숫자, 두 줄 버튼 문구로 줄바꿈과 잘림을 확인한다. 중요한 값·오류·동작 이름이 생략되면 전체 내용을 볼 수 있는 경로를 둔다. 키보드 포커스가 배경에 묻히거나 다른 요소에 가려지지 않는지 실제 화면에서 확인한다.

## 수치 참고와 한계

일반 텍스트 대비는 4.5:1, WCAG에서 정의한 큰 글자는 3:1을 참고한다. 실제 전경·배경 조합으로 계산하며, 그림을 눈으로 보는 것만으로 통과를 선언하지 않는다. 적용 예외와 정의는 원문을 확인한다.

포인터 대상 크기는 WCAG 2.2의 24×24 CSS px 기준과 간격 등 예외를 함께 확인한다. 이 키트에서는 주요 터치 동작을 편하게 누르도록 가능하면 약 44px 이상을 설계 출발점으로 권장한다. 44px를 모든 요소에 적용되는 WCAG 최소값으로 설명하지 않는다.

## 출처

- [W3C: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 텍스트 대비 4.5:1·큰 글자 3:1 및 예외를 뒷받침한다.
- [W3C: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 포인터 대상 24×24 CSS px 및 예외를 뒷받침한다.

나머지 토큰과 구성요소 선택은 이 키트의 설계 제안이다. 이 문서나 CSS 예시 사용만으로 WCAG 준수를 인증하지 않는다.
