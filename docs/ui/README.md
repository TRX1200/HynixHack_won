# 필요한 UI 지침만 고르기

먼저 기존 화면과 사용자의 핵심 행동 하나를 확인한다. 기존 디자인, 컴포넌트, 언어와 실행 환경을 유지하고, 과제의 기능 오류를 먼저 고친다. 화면이 필요하지 않은 계산·CLI 작업에 대시보드를 덧붙이지 않는다.

처음에는 [디자인 기본값](DESIGN_SYSTEM.md)과 아래에서 목적에 맞는 문서 하나만 읽는다. 모든 문서를 한 번에 읽거나 모든 화면을 카드로 만들 필요는 없다.

| 사용자의 핵심 행동 | 다음 문서 | 먼저 만들 것 |
| --- | --- | --- |
| 지표를 비교하고 원인을 찾는다 | [대시보드](DASHBOARD_UX.md) | 실제 데이터로 답하는 질문 하나 |
| 기록을 찾고 수정하거나 제출한다 | [운영자와 일반 사용자](ADMIN_USER_UX.md) | 목록→상세→작업 또는 입력→확인→결과 |
| 위치를 찾거나 둘러본다 | [선택 기준](DECISION_ROUTER.md) | 지도가 필요한 이유와 목록 대안 확인 |
| 소개·탐색·목적 불명 | [선택 기준](DECISION_ROUTER.md) | 필요한 정보와 다음 행동 확인 |

좁은 화면에서 구조가 깨지면 [반응형](RESPONSIVE.md)을 추가한다. 구현을 마칠 때 [시각 검토](VISUAL_REVIEW.md)를 별도로 진행한다. 기본 읽기 범위는 관련 문서 2~3개이며, 검토 범위는 실제 작업에 따라 늘린다.

AI에게 다음처럼 요청할 수 있다. 아래는 터미널 명령이 아니다.

> 기존 코드와 실행 방법부터 확인해줘. 사용자의 핵심 목표와 기존 디자인을 요약하고, UI가 필요한지 판단해줘. 이 폴더에서 관련 지침 2~3개만 선택해 읽어. 기존 스택으로 핵심 흐름 하나를 구현하고 기능 검증과 실제 화면 검토 결과를 나눠 보고해. 실행·캡처하지 못한 항목은 NOT_RUN으로 남겨.

선택을 돕는 선택적 CLI와 입력 형식은 [선택 기준](DECISION_ROUTER.md)에 있다. 문서와 CLI 추천은 설계 보조이며, 접근성 준수 인증이나 기능 구현의 증거가 아니다.

## 근거 범위

이 문서의 작업 순서와 문서 선택은 이 키트의 실무 지침이다. 수치가 있는 접근성 참고 기준과 지원하는 범위는 [디자인 기본값](DESIGN_SYSTEM.md) 및 [반응형](RESPONSIVE.md) 하단의 W3C 링크에 명시한다.
