# 좁은 화면에서 핵심 작업 유지하기

기존 반응형 규칙을 확인한 뒤 좁은 화면에서 먼저 핵심 흐름을 완성한다. 데스크톱 화면을 단순 축소하지 않는다. 콘텐츠가 더 이상 읽히지 않거나 동작이 겹치는 지점에 따라 배치를 바꾼다.

## 검토 폭

| CSS px 폭 | 확인할 것 |
| --- | --- |
| 320 | 긴 한글·오류 문구·버튼이 화면 밖으로 사라지지 않는지 |
| 390 | 메뉴·폼·주요 행동을 실제로 사용할 수 있는지 |
| 768 | 열 수가 바뀔 때 읽기 순서와 상세 패널이 유지되는지 |
| 1440 | 지나치게 긴 본문 줄, 빈 공간, 펼쳐진 표의 가독성 |

이 네 폭은 키트의 검토 표본이며 모든 기기 지원을 증명하지 않는다. 높이와 확대 상태도 기록하고, 프로젝트가 요구하는 추가 환경이 있으면 함께 검토한다.

## 구체적인 조정

- 기본 내용은 한 열로 읽히게 한다. 나란한 입력은 필요에 따라 쌓고, 버튼 이름·단위·오류는 줄바꿈할 수 있게 한다.
- 긴 한글 제목·공백 없는 ID·큰 숫자·번역 문구로 시험한다. 잘라야 한다면 중요한 정보를 다시 볼 수 있는 상세 경로를 둔다.
- 표와 지도처럼 2차원 관계가 필요한 부분은 제한된 영역 안에서 스크롤·이동할 수 있게 한다. 페이지 전체에 무조건 가로 스크롤을 허용하는 근거로 쓰지 않는다.
- 큰 표는 필요한 열 선택·요약+상세·국소 스크롤 중 목적에 맞는 방식을 고른다. 비교가 중요한 표를 무조건 카드 목록으로 바꾸지 않는다.
- 지도 주변 제목·검색·목록·설명은 화면 폭에 맞춰 배치한다. 지도 조작 없이도 가능한 핵심 탐색 경로를 검토한다.
- 고정 헤더·하단 버튼·팝업이 본문·포커스·제출 동작을 가리지 않게 한다. 키보드로 열고 닫고 다음 동작으로 이동해 본다.

지원하는 실행·브라우저 도구로 실제 렌더링을 확인한다. CSS 파일을 읽거나 빌드가 성공한 것만으로 반응형 검토를 PASS라 하지 않는다. 화면을 확인하지 못한 폭과 상태는 [시각 검토](VISUAL_REVIEW.md)에 NOT_RUN으로 남긴다.

## 출처

- [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html): 세로 스크롤 콘텐츠의 320 CSS px 너비와, 의미·사용에 2차원 배치가 필요한 부분의 예외를 뒷받침한다. 표의 개별 셀이나 주변 본문까지 모두 예외가 되는 것은 아니다.
- [W3C: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 포인터 대상 24×24 CSS px 기준과 예외를 설명한다. 터치 조작 편의를 위한 크기 선택은 [디자인 기본값](DESIGN_SYSTEM.md)을 참고한다.

이 체크리스트만으로 접근성 준수나 모든 장치 지원을 인증하지 않는다.
