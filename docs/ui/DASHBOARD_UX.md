# 대시보드는 답할 질문에서 시작하기

사용자가 내릴 결정 하나를 먼저 적는다. 예를 들어 “선택한 기간에 처리 지연이 어느 구간에서 늘었는가?”처럼 데이터가 답할 수 있는 질문을 고른다. 실제 데이터에 없는 매출·성장률·가동률을 장식용 KPI로 만들지 않는다.

## 지표 정의를 먼저 확인

| 항목 | 화면에 드러낼 내용 |
| --- | --- |
| 의미 | 무엇을 세거나 계산했는지, 데이터 출처 |
| 기간 | 시작·종료, 집계 간격과 필요한 시간대 |
| 단위 | 건·명·초·원 등; 축·표·요약에서 일치 |
| 분모 | 비율 계산 대상, 중복 제외 여부, 필터 적용 범위 |
| 결측 | 0과 미수집·계산 불가를 구별, 제외 건수 표시 |
| 비교 | 같은 길이·조건의 비교 기간, 증감의 좋은/나쁜 의미 |
| 상세 | 요약 값에서 근거 기록으로 이동하는 경로 |

분모가 0이거나 자료가 없으면 임의의 0%·증가율을 표시하지 않는다. “계산 불가”와 이유를 보여준다. 예시 데이터는 화면과 검증 기록에 예시임을 표시하고, 실제 결과와 섞지 않는다.

## 정보 순서

1. 페이지 제목과 현재 기간·필터를 표시한다.
2. 결정에 필요한 핵심 요약만 둔다. 지표 수를 채우기 위해 카드를 늘리지 않는다.
3. 추세는 선, 범주 비교는 막대, 정확한 값과 상세 기록은 표 등 목적에 맞는 표현을 고른다.
4. 요약→선택한 구간·범주→상세 기록으로 이어지고, 돌아오면 필터가 유지되게 한다.

막대·색·아이콘만으로 뜻을 전달하지 않는다. 범례·축·단위·텍스트 값을 함께 확인한다. 좌표가 존재한다는 이유만으로 지도를 기본 화면으로 선택하지 않는다. 위치 판단이 핵심일 때만 지도와 목록 연결을 검토한다.

## 실제 값으로 검증

같은 필터를 적용한 작은 원본 집합으로 합계·비율·표의 기록 수를 대조한다. 필터 변경 후 제목·요약·차트·상세가 같은 범위를 반영하는지 본다. 빈 결과에는 필터 해제 같은 다음 행동을, 로딩에는 진행 상태를, 오류에는 재시도와 원인 범위를 제공한다. 데이터 조회 실패를 값 0으로 숨기지 않는다.

처음에는 [디자인 기본값](DESIGN_SYSTEM.md)과 이 문서만 읽고 핵심 질문 하나를 구현한다. 완료 전 [시각 검토](VISUAL_REVIEW.md)에서 실제 화면을 별도 확인한다.

## 근거 범위

이 문서는 범용 데이터 표현·검증 작업 지침이다. 특정 산업 지표의 정의나 정확성은 제공된 명세·원본 자료로 확인해야 한다. 접근성 수치의 출처는 [디자인 기본값](DESIGN_SYSTEM.md#출처)에 있다.
