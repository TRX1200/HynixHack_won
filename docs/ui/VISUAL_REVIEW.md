# 기능 검증과 실제 화면 검토 나누기

기능이 맞는지와 화면을 읽고 조작할 수 있는지는 따로 확인한다. 빌드·API 테스트 통과는 실제 화면 검토를 대신하지 않는다. 멋진 스크린샷도 계산·저장·권한 검증의 증거가 되지 않는다.

## 두 가지 검토

| 검토 | 실제로 확인할 것 | 근거 |
| --- | --- | --- |
| 기능 QA | 입력→처리→결과, 계산·저장, 오류 복구, 요구된 서버 권한 | 실행 명령·응답·테스트 로그·fixture |
| 시각 QA | 배치·읽기 순서, 색·글자·간격, 잘림·겹침, 상태별 표현 | 실제 렌더링 관찰·스크린샷·뷰포트 |

[기록 템플릿](../../templates/ui/visual_review.json)을 선택적으로 사용한다. 기본 NOT_RUN을 실제 확인한 항목만 바꾼다. 프로젝트가 요구하는 테스트와 호스트 규칙이 우선이다.

## 화면에서 확인할 상태

- 정상: 핵심 행동 하나를 끝까지 수행하고, 값·단위·결과가 일치하는지 본다.
- 긴 콘텐츠: 긴 한글 이름·설명, 큰 숫자, 공백 없는 식별자가 표·버튼·카드를 깨뜨리지 않는지 본다.
- empty: 데이터 없음과 필터 결과 없음을 구별하고 다음 행동을 제공한다.
- loading: 진행 상태가 보이고, 중복 제출이나 갑작스러운 레이아웃 붕괴가 없는지 본다.
- error: 원인 범위와 재시도·수정 경로가 보이며 입력을 불필요하게 잃지 않는지 본다.
- 키보드: Tab 이동 순서·보이는 포커스·컨트롤 동작·팝업 닫기·이후 포커스 위치를 실제로 확인한다.
- 반응형: 320·390·768·1440 CSS px 중 해당 화면의 실제 검토 폭과 높이를 기록한다. 표·지도 국소 스크롤과 주변 본문을 구별한다.

상태가 프로젝트에 해당하지 않으면 이유와 함께 NA로 남긴다. 실패 상태는 허용된 테스트 fixture나 로컬 테스트 수단으로 재현하며, 실제 자료를 훼손하지 않는다.

## 증거와 결과

호스트가 허용하는 브라우저·캡처 수단으로 실제 실행 화면을 캡처한다. 경로/화면, 사용한 데이터 범위, 폭×높이, 상태, 관련 변경 버전과 로컬 증거 파일을 연결한다. 합성 이미지나 디자인 시안은 실행 증거가 아니다. 민감한 내용은 캡처에서 제외하고, 자료와 검증 결과를 외부로 전송하지 않는다.

PASS는 적힌 범위에서 기대 동작을 관찰한 경우, FAIL은 불일치를 재현한 경우다. 실행·관찰하지 못했으면 NOT_RUN, 필요한 환경·권한이 없어 진행할 수 없으면 BLOCKED와 이유를 기록한다. 캡처가 불가능하면 스크린샷 항목은 NOT_RUN으로 남기고 실제 관찰 여부를 따로 적는다. 실패를 수정한 뒤 같은 조건으로 다시 확인한다.

완료 보고에는 “기능 QA: … / 시각 QA: … / 남은 NOT_RUN·BLOCKED: …”를 구별한다. 한 화면의 통과를 전체 서비스 통과로 확장하지 않는다.

## 근거 범위

이 문서의 상태·증거 형식은 이 키트의 작업 규칙이다. 대비·대상 크기·리플로의 W3C 근거는 [디자인 기본값](DESIGN_SYSTEM.md#출처)과 [반응형](RESPONSIVE.md#출처)에 있으며, 이 검토는 준수 인증이 아니다.
