# 보고서 작성 요령

## 기본 구조
1. 결론/권고: 질문에 대한 답부터 2~4문장.
2. 핵심 결과: 수치·조건·근거 위치를 함께 표시.
3. 범위/입력: 포함·제외 범위, 기간, 단위, 집계 단위.
4. 방법/선택 이유: 대안과 trade-off를 필요한 만큼만 설명.
5. 검증: 기대값·실제값·상태·실행 근거.
6. 한계/미확인: 결론이 바뀔 조건, 아직 안 한 검사.
7. 다음 조치: 실행 가능한 담당/검증/우선순위.

## 표현 교정
| 과장 또는 불명확 | 권장 표현 |
|---|---|
| '완벽하게 검증했다' | '명시한 정상/경계/오류 입력 8개에서 기대 결과와 일치했다. 대규모 부하는 미검증이다.' |
| '불량 원인은 온도다' | '관측 구간에서 온도와 불량률이 함께 변했다. 원인 확인을 위한 추가 통제가 필요하다.' |
| '최적해다' | '정의한 유한 모델을 완전 탐색한 결과다. 할인/고정비는 모델에 포함되지 않았다.' |
| 'AI가 이렇게 말했다' | '원문 정책 3쪽의 조건과 실행 결과 test_log의 CASE-03을 기준으로 판단했다.' |
| '문서에 없다' | '현재 추출·검색 범위에서는 확인하지 못했다. 읽지 못한 문서 2개가 남았다.' |

위 숫자는 문장 형식의 예시입니다. 실제 보고서에는 실제 검사 수만 씁니다.

## 표/그림
제목만 보아도 무엇을 비교하는지 알 수 있게 씁니다.
축·단위·범례·기간·표본 수를 표시합니다. 비율은 분모를 함께 제시합니다.
이미지 비교는 원본/조건/표시 좌표를 남깁니다. 의심 위치 표시는 정답 라벨과 구분합니다.
장식보다 읽기 순서와 근거의 연결이 우선입니다. 그림 없이 충분하면 만들지 않습니다.

## 형식별 최소 산출물
- 분석: REPORT + 계산 코드 + 입력 식별/해시 + 결과표 + 테스트 로그.
- 규정 판단: 대상별 결론/규칙/예외/출처/미확정 표.
- 앱: 실행법 + 완료 기능 + 핵심 테스트 + 수동 UI 확인 내역 + 알려진 한계.
- 이미지: 원본 목록 + 영역 좌표/표시 이미지 + 판정 근거 + 재검토 목록.
- 최적화: 변수/목적/제약 + 해 + 독립 검사 + 상태(최적/가능/미확정).
항상 실제 과제의 필수 파일명·형식을 우선합니다. 모든 템플릿을 제출하지 마십시오.

## 양식
`templates/REPORT.md`, `APP_README.md`, `DECISION_MEMO.md`, `SLIDE_PLAN.md`, `report.json`을 선택해 사용합니다.
`python tools/run.py report work/report.json --format html --out work/report.html`로 정적 HTML을 만들 수 있습니다.
HTML은 입력값을 escape하고 외부 자산/JavaScript를 포함하지 않습니다. 내용의 정확성을 검증하는 기능은 아닙니다.
PDF/PPTX가 필수라면 해당 환경의 허용된 제작/변환 수단을 사용하고 실제 페이지를 확인하십시오.
이 키트는 DOCX/PPTX/PDF 최종 제작기를 포함하지 않습니다.
