# 준비 PC에서 할 작은 연습

이 문서는 공개 합성 연습입니다. 본시험 문제 유형이나 기출이 아닙니다.
정답/검사 코드를 이미 본 예제이므로 독립된 최종 성능 평가로 사용하지 마십시오.

## 1. CSV와 결합
- examples/sample.csv를 profile하고 중복 ID와 빈 측정값을 설명합니다.
- join_left/right의 예상 left join 행 수를 손으로 센 뒤 join-audit 결과와 대조합니다.
- '중복을 지우면 해결'이라고 하지 말고, 각 테이블의 한 행이 무엇인지를 먼저 정의합니다.

## 2. 문서와 근거
- examples/policy.md를 추출하고 '임시 사용자'를 검색합니다.
- source locator와 quote로 원문을 다시 찾습니다.
- 기준일/예외 기간/기능 요구를 구분합니다. 제공되지 않은 사용자 속성은 가정하지 않습니다.

## 3. 순서
- order_ambiguous.json을 풀고 가능한 순서가 두 개 이상인 이유를 설명합니다.
- order_cycle.json을 풀고 왜 실행 가능한 순서가 없는지 설명합니다.
- 도구가 고른 사전순과 업무 규칙을 구분합니다.

## 4. 작은 배정
- assignment.json을 손으로 검토한 뒤 assign을 실행합니다.
- max-states를 작게 줄였을 때 상태가 어떻게 달라지는지 확인합니다.
- 기능·용량 제약을 일부러 어긴 해를 check-assignment에 넣습니다.
- 이 모델에 고정비/할인을 넣으려면 무엇을 바꿔야 하는지 설명합니다.

## 5. 이미지
- 본인이 만든 합성 도형 2개로 contact-sheet/crop/diff를 확인합니다.
- 동일 이미지, 위치 이동, 크기 변경, 작은 점 추가를 나누어 시험합니다.
- '차이 픽셀 비율'을 실제 불량률로 해석하지 않습니다.
- 실제 기밀 검사 이미지로 연습 결과를 공개 저장소에 추가하지 않습니다.

## 6. 개발/디버깅
- 작은 합산 함수에 빈 입력·비수치 입력 정책을 정의합니다.
- 먼저 실패 테스트를 만든 뒤 함수/테스트를 실제 실행합니다.
- 프로그램이 실행된다는 것과 기대값이 맞는다는 것을 나누어 설명합니다.

## 마무리: AI 없이 설명
핵심 요구, 선택 이유, 처리 흐름, 실제 검증, 한계의 다섯 문장을 직접 작성합니다.
모든 유형을 오늘 완주하는 것보다, 문서/CSV/검증의 기본 흐름을 확실히 이해하는 것을 우선합니다.
