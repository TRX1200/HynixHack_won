# 처음 15분: 브라우저 IDE에서 길을 익히기

개인 연습을 위한 짧은 준비 순서입니다. 특정 운영 일정이나 이용 시간을 설명하는 문서는 아닙니다.
목표는 **현재 위치 확인 → 공개 키트 읽기 → 작은 실행 한 건 확인**입니다.
모든 도구·라이브러리·MCP를 설치하는 것이 목표가 아닙니다.

제공된 브라우저 IDE에 편집기와 터미널이 있다면 개인 PC에 VS Code를 따로 설치할
필요가 없습니다. Python은 원격 IDE에서 확인합니다. 개인 PC의 설치 여부로 판단하지 마세요.

## 0~3분: 내가 입력하는 칸 확인

- **편집기:** 파일을 읽고 수정하는 곳.
- **터미널/셸:** `pwd`, `ls`, `python3 --version`, `codex` 같은 프로그램 명령을 넣는 곳.
- **Codex AI 입력칸:** Codex가 실행된 뒤 자연어 요청을 넣는 곳.
- **MCP 설정 탭:** JSON을 저장하는 곳.
- **Helper/도움말:** 환경 사용법과 허용된 설치·재시작 방법을 확인하는 곳.

이미 Codex가 열려 있으면 새로 여러 개를 띄우지 마세요. 셸 상태라면 실제 작업
폴더를 확인한 뒤 **터미널에 `codex`**로 시작합니다. `/codex`는 아닙니다.
`/model`, `/mcp`, `/skills`는 해당 Codex가 지원할 때 **Codex 입력칸**에 넣는 명령입니다.
셸에서 `/model`을 입력해 파일 오류가 나도 프로그램을 새로 설치해야 한다는 뜻은 아닙니다.

Codex가 한 터미널을 사용 중이면 아래 셸 명령을 직접 입력할 때 `+`로 **별도 터미널**을
열거나, AI에게 “다음 명령을 터미널에서 실행해 주세요”라고 맡기세요.
AI 입력칸과 셸 입력칸을 오가려고 실행 중인 앱 서버 터미널을 닫지 마세요.

**AI 입력문 — AI가 이미 열렸다면:**

> 이 IDE에서 현재 작업 폴더와 과제 README 위치를 확인해 주세요.
> 아직 파일·설정·패키지를 바꾸지 말고 편집기·터미널·AI 입력칸을 구분하는 방법을 짧게 알려 주세요.

## 3~6분: 실제 실행기와 공개 자료 위치 확인

**터미널에서 한 줄씩:**

```bash
pwd
ls
python3 --version
python --version
node --version
```

Python 3.10 이상이 출력되는 이름을 기억하세요. 아래는 `python3` 예시이며,
`python`만 맞으면 그 이름으로 바꿉니다. 둘 다 없으면 아래 **Python 없는 경로**로 갑니다.

호스트가 허용한 실제 공개 주소를 [Clone 절차](QUICKSTART_KO.md#3-공개-자료를-원격-ide-안으로-가져오기)에 따라
v2 저장소를 새 `_toolkit` 폴더로 Clone합니다. tools/docs/.agents 소스가 직접 있으므로 압축 해제는 필요 없습니다.
이미 받았다면 다시 Clone하거나 덮어쓰지 않습니다. 개인 PC ZIP 업로드나 키 입력은 사용하지 않습니다.

## 6~10분: 하나만 실행하거나 설명서부터 읽기

### Python 3.10 이상이 있는 경로 — 터미널

```bash
python3 _toolkit/tools/run.py doctor
python3 _toolkit/tools/run.py csv-profile _toolkit/examples/sample.csv --key item_id
```

실제 출력·오류를 확인하세요. 합성 CSV 예제이므로 과제 원본을 수정하지 않습니다.
패키지를 한꺼번에 설치하지 않습니다. 선택 패키지가 없다는 메시지는 기본 작업 전체의 실패와 다릅니다.

### Python 없는 경로 — AI 입력문

> `_toolkit/.agents/skills/wb-start/SKILL.md`와
> `_toolkit/.agents/skills/wb-verify/SKILL.md`를 직접 파일로 읽어 주세요.
> `__KIT_ROOT__`는 실제 원본 키트 루트로 해석하고 읽은 경로를 알려 주세요.
> Python 도구는 아직 실행할 수 없다고 표시해 주세요. 기존 프로젝트 언어와 실제 설치된 실행기를 먼저 사용하고,
> Node가 있으면 필요한 작은 JavaScript 검사로 시작해 주세요. Python이 꼭 필요한 기능만 따로 적어 주세요.

Helper에는 **사용 가능한 Python 명령과 허용된 프로젝트 설치 방법**을 확인합니다.
설치가 가능하다는 답만으로 성공이라고 기록하지 말고 버전·작은 실행을 확인해야 합니다.
Python이 없어도 AI가 Markdown Skill을 읽을 수 있습니다. Python MCP를 Node로 실행할 수 있다는 뜻은 아닙니다.

## 10~13분: 선택 Skill 두 개와 작은 요청

등록이 허용되고 Python이 있다면 **과제 루트의 터미널**에서 실행합니다.

```bash
python3 _toolkit/tools/install_skills.py --project . --skills wb-start wb-verify
```

실제 `.agents/skills` 생성과 키트 경로 치환, AI의 인식 여부를 확인합니다.
[Skill 적용 절차](QUICKSTART_KO.md#4-skill은-우선-두-개만)를 보세요.
자동 인식이 안 되면 설치 반복 대신 위 “직접 읽기” 요청을 사용합니다.

**AI 입력문:**

> README 기준으로 필수 결과·제약·검사 한 가지를 먼저 정리해 주세요.
> 가장 작은 동작 한 건부터 실제 실행하고 실제 결과와 아직 못 한 것을 구분해 주세요.
> 기존 언어·도구를 사용하고 새 설치는 필요한 이유가 생겼을 때만 검토해 주세요.

## 13~15분: 성공 기준과 복구 방법 남기기

다음 다섯 가지를 허용된 작업 폴더의 개인 준비 메모에 기록합니다. 공개 저장소에 올리지 않습니다.

- 실제 작업 루트와 키트 루트.
- 확인된 실행 명령·버전 또는 없는 실행기.
- 실제 읽은 Skill 두 개의 경로.
- 실제 실행한 작은 명령과 결과, 못 한 항목.
- 다음 세션에서 다시 확인할 설정과 지원 경로.

MCP가 꼭 필요해졌을 때만 [MCP 가이드](MCP.md)를 사용하세요. JSON을 저장한 뒤
실행 중인 Codex에 적용하려면 호스트 안내에 따라 정상 종료·재시작이 필요할 수 있습니다.
앱 서버가 돌아가는 다른 터미널을 닫지 마세요. 다음 세션에도 설정이 유지된다고 가정하지 않습니다.

## 막혔을 때 바로 할 일

| 증상 | 먼저 확인 |
| --- | --- |
| `/model` 등이 파일 오류 | 셸에 넣었는지 확인. `codex` 실행 뒤 해당 AI 입력칸·지원 명령 사용 |
| `python3` 없음 | `python` 버전 확인. 둘 다 없으면 Markdown 직접 읽기와 기존 언어 사용 |
| `_toolkit/tools/run.py` 없음 | `pwd`, `ls`, 실제 Clone 위치 확인. 과제 폴더와 키트 폴더 구분 |
| Skill 복사 후 안 보임 | 실제 경로·호스트 재읽기 안내 확인. 읽었다고 단정하지 않기 |
| MCP 저장 후 안 보임 | JSON·실행기·절대경로·색인·호스트 재적용 절차 확인 |
| 다운로드·설치 차단 | Helper의 허용된 방법 확인. 키·개인 파일 업로드·외부 서비스로 우회하지 않기 |

오류 원문을 AI나 Helper에 보여 주되 토큰·개인키·비공개 주소는 포함하지 마세요.
설치가 막혀도 환경을 통째로 바꾸지 않고 이미 제공된 편집기·AI·언어로 작은 작업을 이어갑니다.
